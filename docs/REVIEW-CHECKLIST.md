# 审核清单

这份清单公开给作者自查——审核者按它审，你照它自查，双方看的是同一张表。审核的对象是**你的仓库在钉死 tag 下的确切字节**，不是你这个人；下一个版本从零再审。

## CI 段（机器查什么）

`scripts/build_index.py --check` 对每个条目做的事，PR 上自动跑，本地可先跑：

- [ ] 条目文件名 = `<id>.json`，`id` 合法（ASCII、无空白、不含 `/` `\` `:`、≤100 字符）、未被占用
- [ ] `repo` 是可解析的 `github.com` 地址；`tag` 存在且内容可取
- [ ] `manifest.json` 合法：`id` 与条目一致、`version` 是 semver 且较上一版递增、`name` / `description` / `author.name` 非空、`category` 属于 `system` / `monitor` / `info` / `dev`
- [ ] `disclosures` 四个键（`network` / `reads` / `writes` / `spawns`）齐全，空的写 `[]` 不省略
- [ ] 板块声明是合法 JSON、能被 Sono 客户端（`SonoKit`）解码：`board` 字段 = 插件 id，`exec.file` = `~/.sono/boards/bin/<id>/<脚本名>`，`refresh.argv` 是非空字符串数组
- [ ] argv 不经 shell：任何 argv 里出现 `sh -c` / `bash -c` 直接失败
- [ ] 脚本是 UTF-8 可读文本（无 NUL、非二进制），文本里没有 `sh -c`
- [ ] 每个文件 ≤ 256KB
- [ ] `README.md` 存在；`preview.json`（若声明）是合法 JSON
- [ ] 机械扫描：脚本里的网络库导入、`curl` / `urllib` / `fetch` 字样、可疑域名字符串，与披露不符 → 转慢线并标记

## 人工段（通读什么）

机器查不了的判断，按披露分级后人来做：

- [ ] **脚本通读一遍**——每一行都要能解释「它为什么在这」
- [ ] **披露与代码一致**（最常见的拒收原因）：访问的网络端点、读写的路径、碰的凭据存储、派生的进程，与 `disclosures` 逐条对得上；多写少写都打回
- [ ] 无凭据外传：token / 密钥只在本机与官方端点之间移动，不发去第三方
- [ ] 密钥不进 argv（执行审计记录完整 argv）
- [ ] `impact` 标注诚实：不可逆或影响别人的动作（退出 App、删除、发送）必须 `high`
- [ ] toggle 语义正确：`title` 命名 `on == true` 时成立的那件事，动作把状态翻到另一侧；`on` 查不到就整个省略该键
- [ ] 数据面品味：headline 不写计数、量放 badge、查不到的不画（用 note 说明原因与修法）、缓存数据标注新鲜度
- [ ] `preview.json` 不虚构能力：示例数据面画的必须是脚本真能产出的形状
- [ ] README 坦率：用途、数据来源、已知边界写清楚，不夸大

## 快线判定条件（机械判定，不靠感觉）

同时满足以下全部 → 快线（Agent 审核流水线通读 + 人工抽查）：

1. `disclosures.network == []`
2. `disclosures.writes == []`
3. `reads` 与 `spawns` 不涉及凭据存储（钥匙串、`.credentials`、token 文件、浏览器 profile）
4. CI 全绿，机械扫描未发现与披露不符的迹象

任一不满足 → 慢线：人工逐行通读，宁积压不降标。

## 拒收线（不是劝改，是拒收）

- 混淆或压缩过的代码、二进制
- 网络端点与披露不符
- 读取披露之外的凭据存储
- 要求提权
- argv 经 shell（`sh -c` / `bash -c`）
- 运行时下载并执行代码
- 与既有插件近似到足以误导的 `id` / 名称

## 审核不覆盖什么（同样公开）

- 审核是通读，**不是形式化验证、不是沙盒、不是担保**。通读读不出来的定向恶意，由 Sono 客户端侧的逐命令授权卡、内容哈希钉死与执行审计兜底——那三样对官方与社区插件无差别生效。
- 审核不评价插件「有没有用」「好不好看」——那是用户用脚投票的事。
